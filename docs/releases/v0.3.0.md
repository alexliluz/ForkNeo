# ForkNeo v0.3.0

ForkNeo v0.3.0 adds a read-only conversion preflight and moves all
source-side safety checks ahead of target repository creation.

## Highlights

### Preview a conversion without remote changes

Use the new option with an explicit name or the default suffix:

```bash
forkneo convert owner/project --name project-independent --dry-run
```

A successful dry run reports:

- the resolved source and proposed target;
- the selected default branch;
- the exact source branch and tag ref count;
- whether Git LFS pointers were detected;
- confirmation that no remote changes were made.

Dry-run mode clones and prunes a temporary mirror and verifies Git LFS
inspection. It does not request destructive confirmation, fetch all LFS
objects, create or update a GitHub repository, push data, or write a migration
report.

### No empty target after source-side preflight failure

Normal conversion now completes these stages before creating the target:

1. mirror clone;
2. unsupported-ref pruning;
3. Git LFS availability and pointer inspection;
4. source LFS object fetch when required.

A failure in those stages reports that no target repository was created.

### Accurate recovery boundaries

ForkNeo distinguishes three outcomes:

- preflight failed before target creation;
- the GitHub create request failed with an uncertain remote outcome, so the
  proposed target must be inspected before retrying;
- target creation succeeded and a later failure kept the target for explicit
  recovery.

Typed post-creation errors retain their original code and message while adding
the target-retention guidance.

## Compatibility

- Node.js 22 or newer remains required.
- Git LFS remains required for every `convert` and `convert --dry-run`
  operation.
- No dependencies were added or upgraded.
- Existing `scan`, `verify`, and normal successful-conversion output remain
  compatible.

## Verification

- 13 test files and 61 tests pass.
- Type checking and the production build pass.
- CLI smoke tests cover the root and `convert` help.
- CI passes on Ubuntu, macOS, and Windows with Node.js 22, 24, and 26.
- A public-fork acceptance run confirmed that the proposed target returned
  HTTP 404 before and after a successful dry run.
